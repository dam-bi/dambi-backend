# 공연장 좌석 구역 테이블 현황

## 목적

공연장별 좌석 구역 정보를 관리한다. 구역 하나가 `venue_seat_section` 테이블의 row 하나에 대응하며, 예를 들어 `1구역 VIP석`이 `A1`부터 `B10`까지의 좌석 범위임을 저장한다.

프론트엔드는 구역 표시 문자열을 조합하지 않고 `sectionCode`와 `gradeCode`를 분리하여 전송한다. 백엔드는 `venueId`, `sectionCode`, `gradeCode`로 구역 정보를 조회해 좌석 범위와 등급 정보를 사용한다.

## 현재 상태

- 현재 실제 Docker 초기화 스키마(`docker/db/init/01-schema.sql`)에는 `venue` 테이블만 있으며, 좌석 구역을 저장하는 테이블은 없다.
- `venue`는 `concert`과 1:N 관계다. 하나의 공연장에서 여러 콘서트가 열릴 수 있다.
- 현재 `concert_price`는 콘서트별 좌석 등급과 가격만 저장하며, 구역 또는 좌석 범위는 저장하지 않는다.
- 좌석, 좌석 재고, 좌석 구역 관련 JPA 엔티티와 API는 아직 구현되지 않았다.
- Docker 환경은 초기화 SQL로 스키마를 생성하고 JPA는 `ddl-auto=validate`로 검증한다. 테이블 구현 시 JPA 엔티티와 `docker/db/init/01-schema.sql`을 함께 변경해야 한다.

## 관계 결정

한 공연장은 여러 구역을 가질 수 있으므로 관계는 다음과 같다.

```text
venue 1 : N venue_seat_section
```

`venue`와 `venue_seat_section`을 1:1로 연결하면 공연장당 구역을 하나만 저장할 수 있어, 구역 하나가 row 하나라는 요구와 맞지 않는다.

## 제안 테이블

```sql
CREATE TABLE venue_seat_section (
    venue_seat_section_id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    venue_id INTEGER NOT NULL,
    section_code VARCHAR(50) NOT NULL,
    section_name VARCHAR(100) NOT NULL,
    grade_code VARCHAR(50) NOT NULL,
    grade_name VARCHAR(100) NOT NULL,
    row_from VARCHAR(10) NOT NULL,
    row_to VARCHAR(10) NOT NULL,
    seat_no_from INTEGER NOT NULL,
    seat_no_to INTEGER NOT NULL,
    CONSTRAINT fk_venue_seat_section_venue
        FOREIGN KEY (venue_id) REFERENCES venue (venue_id),
    CONSTRAINT uq_venue_seat_section
        UNIQUE (venue_id, section_code, grade_code)
);
```

### 저장 예시

| venue_id | section_code | section_name | grade_code | grade_name | row_from | row_to | seat_no_from | seat_no_to |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 1 | 1구역 | VIP | VIP석 | A | B | 1 | 10 |
| 1 | 2 | 2구역 | R | R석 | C | D | 1 | 12 |

첫 번째 row는 `1구역 VIP석`의 좌석 범위가 A행부터 B행까지이며, 각 행의 좌석 번호 범위가 1부터 10까지라는 의미다.

## 조회 기준

프론트 요청 예시:

```json
{
  "sectionCode": "1",
  "gradeCode": "VIP"
}
```

백엔드는 콘서트가 연결된 `venueId`와 위 두 코드를 사용해 하나의 구역 row를 조회한다. 구역 또는 등급 조합이 없으면 요청을 실패 처리한다.

`"1구역-VIP석"`은 화면 표시용 값이며, 공백·대소문자·표기 차이로 조회가 깨질 수 있으므로 DB 조회 키로 사용하지 않는다.

## 구현 전 확인할 사항

- `A1~B10`이 A행과 B행의 1번부터 10번까지를 뜻하는지 확정한다.
- 통로, 결번, 비연속 좌석이 존재하면 시작·끝 범위 컬럼만으로 표현할 수 없다. 이 경우 개별 좌석 테이블 또는 별도 범위 테이블이 필요하다.
- 동일 구역에 여러 좌석 범위가 필요하면 `venue_seat_section` 1건에 범위 테이블을 추가할지 결정한다.
